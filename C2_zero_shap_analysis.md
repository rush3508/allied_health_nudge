## 2. Feature Construction (from 02_feature_engineering.ipynb)

### zero_allied_health_flag (SHAP=0.000326)
Binary: 1 if member made zero allied health claims in past 6 months.
Constructed as: (allied_health_claims_6m == 0).astype(int)
Mean: ~19% 

### high_gp_low_allied (SHAP=0.000051)
Binary: 1 if high GP utilisation (>4 visits in 6m) AND zero allied health claims.
Constructed as: (gp_visits_6m > 4) & (allied_health_claims_6m == 0)
Mean: ~2-3% (very rare)

### Condition x Zero Allied Health Flags (SHAP 0.0-0.000134)
msk_zero_allied       = has_msk_flag * zero_allied_health_flag   (mean=0.028)
metabolic_zero_allied = has_metabolic_flag * zero_allied_health_flag (mean=0.065)
mh_zero_allied        = has_mh_flag * zero_allied_health_flag    (mean=0.011)
comorbid_zero_allied  = comorbidity_count * zero_allied_health_flag
age_zero_allied       = age * zero_allied_health_flag

### any_benefits_remaining (SHAP=0.0)
Binary: 1 if sessions_remaining_total > 0.
Mean = 100% (constant, zero variance). ALL synthetic members have unused sessions.

### CRITICAL FINDING: benefit_utilisation_rate == allied_health_utilisation_rate

## 3. DGP Analysis (acute_events.py)

The label (acute_event) is generated by:
  background_risk = BASE_RATE[condition_cluster] * age_amplifier(age) * comorbidity_amplifier(count)
    where BASE_RATE: Healthy=0.04, MSK=0.18, Metabolic=0.14, MH=0.12, Mixed=0.26
    age_amplifier = exp(0.014 * (age - 40))
    comorbidity_amplifier: stepwise {0:1.0, 1:1.3, 2:1.75, 3:2.2}
  protection = exp(-1.5 * overall_utilisation_rate)
  P(acute_event) = min(background_risk * protection, 0.85)
  acute_event ~ Bernoulli(P)

overall_utilisation_rate = total_sessions_used / total_sessions_entitled (lifetime, all 4 modalities).

KEY INSIGHT: The DGP uses ONLY ONE utilisation variable: lifetime aggregate utilisation rate.
The protection curve is exponential: exp(-1.5 * util). This means:
  util=0.00 -> protection=1.000 (no risk reduction)
  util=0.25 -> protection=0.687 (31% reduction)
  util=0.50 -> protection=0.472 (53% reduction)
  util=1.00 -> protection=0.223 (78% max protection)

All 6 binary nudge features are derived from this same underlying signal:
- zero_allied_health_flag = indicator(6-month utilisation ~ 0)
- any_benefits_remaining = indicator(lifetime utilisation < 1.0) -- constant
- condition-zero flags = interaction(condition, utilisation ~ 0)
- high_gp_low_allied = interaction(high GP, utilisation ~ 0)

## 4. Root Cause Analysis

### 4a. PRIMARY: Information Redundancy (Not a Tree Limitation)
The continuous utilisation_rate contains ALL information in the binary flags AND more.
A decision tree splitting on utilisation_rate <= 0.0 recovers the exact partition of
zero_allied_health_flag == 1, while also being able to split at 0.25, 0.50, etc.
The continuous feature provides strictly richer signal. This is genuine information
redundancy, not a tree model failing to discover interactions.

### 4b. Constant Feature: any_benefits_remaining
100% of synthetic members have sessions remaining. This feature has zero variance.
A tree cannot split on a constant feature. SHAP = 0.0 is mathematically correct.
This is a dead feature that should be removed.

### 4c. SECONDARY: Tree Model Dynamics
LightGBM with num_leaves=31 (max depth ~5) and feature_fraction=0.7 has limited
capacity for discovering interactions. However, since the binary flags carry NO
unique information beyond utilisation_rate, even a deeper tree would ignore them.
The binary flags are subsumed by the continuous variable, not by tree shallowness.

### 4d. Splitting Physics
Continuous utilisation_rate provides ~50,000 candidate split thresholds (one per
unique value). Binary flags provide exactly 1 split point each. The exponential
protection curve exp(-1.5*util) is better approximated by multiple splits on the
continuous variable than by a single binary split. Trees naturally select features
that maximize gain, and continuous features with many split points dominate.

### 4e. Collinearity Artifact
benefit_utilisation_rate and allied_health_utilisation_rate are identical (line 317
assigns one to the other). Their different SHAP values (0.109 vs 0.049) are a
TreeExplainer artifact described in Hooker & Mentch (2019): when features are
perfectly correlated, SHAP decomposition becomes unstable and signal is split
arbitrarily based on tree traversal order.

### 4f. Literature Summary
- Lou et al. (2013) "Accurate Intelligible Models with Pairwise Interactions":
  Gradient-boosted trees naturally prefer continuous features over binarized
  counterparts. Binarization discards ordinal information that trees can exploit.
  
- Hooker & Mentch (2019) "Please Stop Permuting Features":
  SHAP values for perfectly correlated features are split arbitrarily. This explains
  why identical utilisation rates get different SHAP values.
  
- Lundberg et al. (2020) "From local explanations to global understanding":
  TreeExplainer's interventional SHAP can produce misleading results when features
  are deterministic functions of each other.
  
- Hastie et al. (2009) "Elements of Statistical Learning" Section 10.11:
  Trees handle continuous features better than discretized ones. Discretization
  (binarization) loses information and increases variance.

## 5. Proposed Feature Redesign

### Design Principle
Move from binary "has condition AND zero utilisation" to continuous condition-specific
utilisation gaps. The new features measure the gap between a member's condition and
their use of the clinically APPROPRIATE modality (MSK->physio, Metabolic->dietetics,
MH->psychology), aligned with the modality recommendation logic in 05_scoring_output.

### 5a. NEW: Modality-Specific Utilisation Rates (CONTINUOUS, 4 features)

```python
features['physio_utilisation_rate'] = (
    features['sessions_used_physio'] / features['sessions_entitled_physio']
).fillna(0).clip(0, 1)

features['dietetics_utilisation_rate'] = (
    features['sessions_used_dietetics'] / features['sessions_entitled_dietetics']
).fillna(0).clip(0, 1)

features['psychology_utilisation_rate'] = (
    features['sessions_used_psychology'] / features['sessions_entitled_psychology']
).fillna(0).clip(0, 1)

features['chiro_utilisation_rate'] = (
    features['sessions_used_chiro'] / features['sessions_entitled_chiro']
).fillna(0).clip(0, 1)
```

These capture modality-specific behaviour that the aggregate utilisation_rate
obscures. A member using 100% of chiro but 0% of physio has aggregate utilisation=25%
but very different risk profile than someone evenly using 25% across all modalities.

### 5b. NEW: Appropriate Modality Gap (CONTINUOUS, 1 feature)

```python
# For each member, utilisation of the modality matched to their condition
conditions = [
    features['has_msk_flag'] == 1,
    features['has_metabolic_flag'] == 1,
    features['has_mh_flag'] == 1,
]
choices = [
    features['physio_utilisation_rate'],
    features['dietetics_utilisation_rate'],
    features['psychology_utilisation_rate'],
]
features['appropriate_modality_utilisation'] = np.select(conditions, choices, default=0.0)

# Gap: 1.0 = zero use of needed modality, 0.0 = fully using it
features['condition_utilisation_gap'] = 1.0 - features['appropriate_modality_utilisation']
```

This is the SINGLE most important new feature. It directly measures the nudge hypothesis:
"Is this member missing out on the allied health service they clinically need?"

### 5c. NEW: Condition-Specific Continuous Gaps (3 features)

```python
# Replace msk_zero_allied (SHAP=0.000134), metabolic_zero_allied (SHAP=0.0),
# and mh_zero_allied (SHAP=0.000058)
features['msk_physio_gap'] = (
    features['has_msk_flag'] * (1.0 - features['physio_utilisation_rate'])
)
features['metabolic_dietetics_gap'] = (
    features['has_metabolic_flag'] * (1.0 - features['dietetics_utilisation_rate'])
)
features['mh_psych_gap'] = (
    features['has_mh_flag'] * (1.0 - features['psychology_utilisation_rate'])
)
```

CONTINUOUS (0 to 1), replacing the old binary (0 or 1) condition*zero flags.
A member with MSK using 60% of physio has gap=0.4. Old flag would be 0
(because they DO have some allied health claims), losing the signal entirely.

### 5d. NEW: Nudge-Eligible Binary Flags (3 features, for scoring alignment)

```python
features['nudge_eligible_msk'] = (
    (features['has_msk_flag'] == 1) &
    (features['sessions_remaining_physio'] > 0) &
    (features['physio_utilisation_rate'] <= 0.20)
).astype(int)

features['nudge_eligible_metabolic'] = (
    (features['has_metabolic_flag'] == 1) &
    (features['sessions_remaining_dietetics'] > 0) &
    (features['dietetics_utilisation_rate'] <= 0.20)
).astype(int)

features['nudge_eligible_mh'] = (
    (features['has_mh_flag'] == 1) &
    (features['sessions_remaining_psychology'] > 0) &
    (features['psychology_utilisation_rate'] <= 0.20)
).astype(int)
```

These binary flags directly identify the nudge population: has condition, has remaining
sessions in the right modality, and is severely underutilising it (<=20%).
Unlike the old flags which mean "has condition and zero ANY allied health," these mean
"has condition and isn't using the RIGHT allied health service despite having sessions."

### 5e. REPLACE: high_gp_low_allied -> gp_allied_imbalance (1 feature)

```python
# Continuous GP-to-allied imbalance ratio
features['gp_allied_imbalance'] = np.where(
    features['allied_health_claims_6m'] > 0,
    features['gp_visits_6m'] / features['allied_health_claims_6m'],
    features['gp_visits_6m']  # zero allied claims -> max imbalance = gp_visits
).clip(0, 20)
```

Replaces the binary high_gp_low_allied (SHAP=0.000051) with a continuous ratio.
A member with 10 GP visits and 1 allied claim has imbalance=10 (highly GP-skewed).
A member with 2 GP visits and 5 allied claims has imbalance=0.4 (allied-skewed).

### 5f. COLLINEARITY FIX: Deduplicate utilisation rates

REMOVE line 317: features['allied_health_utilisation_rate'] = features['benefit_utilisation_rate']

Keep only ONE aggregate utilisation feature, OR compute them from different sources:
- benefit_utilisation_rate: from benefits table (lifetime sessions used/entitled)
- allied_health_claims_utilisation: from claims table (6-month recent utilisation)

### 5g. OPTIONAL: Modality Alignment Ratio (1 feature)

```python
features['modality_alignment_ratio'] = np.where(
    features['allied_health_utilisation_rate'] > 0.01,
    features['appropriate_modality_utilisation'] / features['allied_health_utilisation_rate'].clip(0.01),
    0.0
)
```

Captures members with high overall utilisation but zero in their needed modality
(e.g., using chiro heavily when they need dietetics for metabolic conditions).

### Why These WILL Work

1. The new features measure a DIFFERENT dimension from aggregate utilisation rate:
   modality-specific behaviour. A member with metabolic condition using 0% dietetics
   but 100% chiro has aggregate utilisation=25% (moderate) but condition_utilisation_gap=1.0
   (maximum). The DGP does not differentiate modalities, but the tree model CAN learn
   that certain utilisation patterns are more protective than others.

2. The continuous gap features provide GRADATION that the old binary flags didn't.
   A tree can split at condition_utilisation_gap <= 0.3 vs <= 0.7, creating nuanced
   risk partitions that the binary "is zero or not" cannot.

3. The nudge_eligible_* flags align features with the scoring notebook's modality
   recommendation logic, creating consistency between model inputs and business outputs.
